## Организация кода

- `task-service.js` - те же 9 функций из ПР2 (`createTask`, `findTaskById`, `getPendingTasks`, `getTaskTitles`, `getTaskStats`, `addTask`, `setTaskCompleted`, `renameTask`, `removeTask`). Про DOM здесь ничего не знает, просто принимает массив и возвращает новый массив или объект с ошибкой.
- `task-selectors.js` - одна функция `getVisibleTasks(tasks, filter)`. Просто `filter()` по полю `completed`, для `all` - копия массива через `slice()`. Данные не трогает, DOM не трогает.
- `task-view.js` - всё, что рисует DOM: `createTaskElement` (одна карточка), `renderTaskList` (весь список через `replaceChildren`), `renderSummary` (пять цифр сводки) и `renderEmptyState` (сообщение о пустом списке/фильтре). Задачи не изменяет, только читает.
- `main.js` - здесь живёт состояние: `currentTasks` (весь актуальный список) и `currentFilter` (какой фильтр выбран сейчас). `renderApp()` берёт эти две переменные, через `getVisibleTasks` считает, что показывать, и вызывает функции отрисовки. `handleTaskListClick` и `handleFilterClick` - обработчики кликов, они меняют `currentTasks`/`currentFilter` и в конце вызывают `renderApp()`.

Обработка события идёт так: клик по кнопке в карточке → `handleTaskListClick` находит саму кнопку через `closest` (даже если кликнули по вложенному `span` с подписью) → достаёт `id` из `data-task-id` ближайшего `li` и проверяет его через `Number.isSafeInteger` → вызывает `setTaskCompleted`/`removeTask` из `task-service.js` → если `ok: true`, сохраняет `result.tasks` в `currentTasks` и вызывает `renderApp()`. Сводка считается в `renderSummary` через `getTaskStats(currentTasks)` - то есть всегда по полному списку, а не по видимой части, поэтому фильтр «В работе» не портит общий прогресс.

## Отладка и клавиатура

**Точка останова.** Строка `const id = Number(card.dataset.taskId);` в `handleTaskListClick` (`src/main.js`). При клике на кнопку «Выполнена» задачи `id=4` в точке останова видно:
- `card.dataset.taskId` = строка `"4"` (тип `string`) - до преобразования;
- после выполнения строки `id` = число `4` (тип `number`);
- `event.target` - это `span.action-label` внутри кнопки (клик обычно попадает именно на текст подписи, а не на пустое поле кнопки);
- `event.currentTarget` - это `ul#task-list`, потому что обработчик назначен именно на контейнер, а не на саму кнопку (делегирование).

На следующей точке останова (после вызова `setTaskCompleted`) видно `result = { ok: true, tasks: [...] }` - новый массив из 4 задач, где у объекта с `id: 4` теперь `completed: true`, а остальные три объекта - это те же самые ссылки, что были в `currentTasks` до вызова (не пересозданы).

**Клавиатура (проверено через автоматизацию, эмулирующую реальные нажатия в браузере):**
- Фокус на кнопке «Выполнена» задачи `id=4` + `Enter` → статус меняется на «Выполнена», фокус остаётся на той же кнопке (`document.activeElement.dataset.action === "toggle"`, `taskId === "4"`) - работает как обычный клик.
- Фокус на кнопке «Удалить» задачи `id=10` + `Space` → карточка удаляется (видимые id стали `[1, 4, 7]`), а поскольку кнопки для восстановления фокуса больше не существует, фокус по правилам `restoreTaskFocus` переходит на активный фильтр (`document.activeElement.dataset.filter === "all"`).

**Отказ для `777` и `4abc`.** Временно поменял `data-task-id` карточки `id=4` на `777` через `dataset.taskId = "777"` (эквивалент правки в панели Elements) и нажал «Удалить»: сообщение `задача не найдена`, данные не изменились (после возврата фильтра «Все» видны всё те же `[1, 4, 7, 10]`). Затем поменял на `"4abc"` и нажал «Выполнена»: сообщение `Некорректный идентификатор задачи`, сводка осталась `2 / 2 / 50.0%` - `Number("4abc")` даёт `NaN`, а не `4`, поэтому `Number.isSafeInteger` отклоняет значение ещё до попытки найти задачу.

В этой работе данные и функции из ПР2 остались без изменений - вся новая работа была в том, чтобы связать уже готовую логику с настоящим интерфейсом. Главное, что стало понятнее: изменение DOM и изменение данных - это две разные вещи. Например, если просто вызвать `element.remove()` у карточки, задача визуально исчезнет, но при следующей перерисовке (например, после смены фильтра) она появится снова, потому что в `currentTasks` она всё ещё есть. Поэтому любое действие идёт по одному и тому же пути: событие → распознать id и действие → вызвать функцию `task-service.js` → если `ok: true`, сохранить новый массив в `currentTasks` → вызвать `renderApp()`, которая уже сама пересоздаёт карточки из актуальных данных.

Отдельно полезным оказалось разделение `currentTasks` (весь список) и видимой выборки, которая считается заново в `getVisibleTasks` при каждой отрисовке и никогда не сохраняется как основной список - иначе кнопка «Все» не смогла бы вернуть скрытые фильтром записи.

Никаких принципиальных ошибок в процессе не было - `task-service.js` перешёл из ПР2 без правок (все 35 проверок прошли сразу), а функции ПР3 сразу проходили автоматические проверки после реализации по контракту из методички.
