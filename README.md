## Задание 1.

Файл `practice-01/js/hello.js` запущен двумя способами: командой `node practice-01/js/hello.js` в терминале и через `index.html` в браузере (вывод во вкладке Console).

| | Node.js | Браузер |
|---|---|---|
| Где появился вывод | В терминале | Во вкладке Console инструментов разработчика, на самой странице текста нет |
| Последняя строка | `Тип document: undefined` | `Тип document: object` |

**Различие:** объект `document` предоставляет браузер (он нужен для работы с HTML-страницей). Node.js запускает JavaScript без страницы и без браузерного DOM, поэтому там `typeof document` даёт `undefined`. JavaScript — это язык, а браузер и Node.js — разные среды, в которых он выполняется.

## Задание 2.

Файл: `practice-01/js/types.js`.

| Выражение | Ожидание до запуска | Фактическое значение | Тип результата | Объяснение |
|---|---|---|---|---|
| `"8" + 2` | `"82"` | `82` (строка) | string | Оператор `+` при наличии строки выполняет конкатенацию, число 2 превращается в текст |
| `"8" - 2` | `6` | `6` | number | Оператор `-` работает только с числами, поэтому строка `"8"` преобразуется в число |
| `Number("8") + 2` | `10` | `10` | number | Строка преобразована явно, затем выполнено обычное сложение |
| `"12" > "3"` | `false` | `false` | boolean | Две строки сравниваются посимвольно как текст: `"1"` меньше `"3"`, поэтому результат `false` |
| `12 === "12"` | `false` | `false` | boolean | Строгое равенство не преобразует типы: число и строка не равны |
| `Number("")` | `0` | `0` | number | Пустая строка преобразуется в 0, поэтому одного `Number()` недостаточно для проверки ввода |
| `Number("text")` | `NaN` | `NaN` | number | Текст нельзя преобразовать в число, получается `NaN` |
| `Boolean("false")` | `true` | `true` | boolean | Любая непустая строка даёт `true`, текст `"false"` не интерпретируется как команда |
| `typeof null` | `"object"` | `object` | string | Историческая особенность языка: `null` — отдельное примитивное значение, но `typeof` возвращает `"object"` |
| `typeof NaN` | `"number"` | `number` | string | `NaN` относится к типу number, поэтому `typeof` не подходит для проверки корректности числа |

Для двух последних строк значение выражения `typeof ...` — это строка, поэтому тип результата самого выражения тоже `string`.

**Как работает цикл:** используется `while (remainingTasks > 0)`. На каждой итерации увеличивается номер дня, вычисляется `doneToday = Math.min(dailyLimit, remainingTasks)` и остаток уменьшается на это значение. Цикл заканчивается, потому что `dailyLimit >= 1` (проверено до цикла), поэтому остаток уменьшается каждый день и не уходит ниже нуля. Благодаря `Math.min` последняя итерация может быть неполной (в варианте 2 в последний день выполнено 3 задачи вместо 4). При недопустимых данных цикл вообще не запускается.

##  Задание 5. 

###  Исходная программа

Исходный вариант с намеренными ошибками дал вывод:

```text
Выполнено: 32
Осталось: -24
Контрольная сумма: 6
```

Исключения не было, но результат неверный (ожидалось `5`, `3`, `10`).

###  Отладка в DevTools

В Chrome DevTools (вкладка **Sources**) точка останова поставлена на строке вычисления `completedTotal` (строка 7). До выполнения строки в Scope видно, что `completedText` и `additionalText` — строки `"3"` и `"2"`. После шага **Step over** значение `completedTotal` равно `"32"` (строка). Затем точка останова была поставлена внутри цикла: видно, как `taskNumber` принимает значения 1, 2, 3, а цикл завершается, не дойдя до 4.

![Остановка программы на точке останова](practice-01\screenshots\debug-breakpoint.png)

###  Найденные ошибки

| Ошибка | Что наблюдалось | Причина | Исправление | Результат после исправления |
|---|---|---|---|---|
| Обработка количества задач | `Выполнено: 32`, `Осталось: -24` | Оператор `+` со строками выполняет конкатенацию: `"3" + "2"` даёт `"32"`. Затем вычитание `"8" - "32"` преобразует строки в числа и даёт `-24` | Явное преобразование: `Number(completedText) + Number(additionalText)` и `Number(plannedText) - completedTotal` | `Выполнено: 5`, `Осталось: 3` |
| Граница цикла | `Контрольная сумма: 6` | Условие `taskNumber < 4` не включает четвёртую задачу: 1 + 2 + 3 = 6 | Условие заменено на `taskNumber <= 4` | `Контрольная сумма: 10` |

###  Результат после исправления

Исправленная версия запущена в Node.js и в браузере, активные точки останова удалены. Вывод:

```text
Выполнено: 5
Осталось: 3
Контрольная сумма: 10
```

Вычисления не заменены константами: значения получаются из исходных строк и цикла.
